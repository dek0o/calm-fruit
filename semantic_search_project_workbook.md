# Проект: семантический поиск товаров по текстовому запросу (query-to-item)

> Рабочий документ заполняется только после выполнения соответствующих ячеек
> Jupyter. Здесь не должно быть результатов из памяти, старого запуска или
> неподтверждённых предположений.

## О проекте

**Бизнес-контекст.** CalmFruits проверяет, улучшает ли векторный поиск товаров
по текстовому запросу существующий поиск по ключевым словам.

**Задача MVP.** Query-to-item: по тексту пользовательского запроса вернуть
top-K карточек товара и в дальнейшем сравнить лексический и семантический
поиск на одинаковом полном каталоге.

**Письменный контракт.** Требования зафиксированы в `AGENTS.md` и
`context/project-month/`. QA-сессия в этой реализации не проводится по
явному решению пользователя.

### Найденные проблемы и риски для недели 2

Сформировано по `text_diagnostics`, `diagnostic_examples`, `manual_sample` и
`longest_descriptions` текущего запуска:

- Перед TF-IDF и эмбеддингами очистить HTML и повторяющиеся пробелы; не
  удалять технические токены и модельные обозначения без отдельного правила:
  ручная выборка содержит смысловые `R 8.6 D -6.00`, `TORX T70`, `100мм`.
- Дедупликация по `imt_id` обязательна; при конфликте описаний выбирать
  информативную строку детерминированно.
- Описания имеют длинный хвост до 754 слов, поэтому во второй неделе явно
  сопоставить политику обрезки с лимитом выбранной модели.
- Строгое правило отбора исключит 58 054 строки; влияние этого сокращения
  каталога необходимо зафиксировать в baseline.
- Цвет не включать в baseline `product_text`: по текущей диагностике его
  консервативное совпадение с названием встречается редко, а влияние следует
  проверять отдельным экспериментом.

## Неделя 2 — базовые поисковые системы и первая оценка

### Подготовка каталога

`catalog_stages` из `notebooks/02_catalog_and_indexes.ipynb` фиксирует путь
от 200 000 исходных строк к 17 967 карточкам MVP и 3 280 карточкам единого
каталога оценки. После очистки и строгого правила заполненности товаров
сохраняется одна строка на `imt_id`; порядок выбора — длина очищенного
описания, затем `nm_id`, затем исходная строка. Очистка изменила 4 805
канонических карточек; десять полнотекстовых примеров лежат в
`artifacts/catalog/before_after_cleaning_examples.html`.

### Индексы поиска

- Лексический: TF-IDF с униграммами и биграммами, 50 000 признаков, L2-норма.
- Семантический: `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`
  на ревизии `e8f8c211226b894fcb81acc59f3b34ba3efd5f42`, 384 измерения,
  batch size 32, CPU, L2-нормализация.
- Обе функции используют общий контракт `search_lexical(query, top_k)` и
  `search_semantic(query, top_k)` и один каталог оценки.

`product_truncation` показал усечение 35,52% товарных текстов при лимите 128
токенов; среди 700 train-запросов усечений нет. Это ограничение baseline.

### Golden-set и протокол

`query_split` делит 700 запросов на 560 development и 140 validation с
группировкой по нормализованному `query_text`; пересечений текстов нет.
Golden-set содержит 2 281 validation-пару. Бинарный порог — `relevance >= 2`,
K — `(1, 3, 5, 10)`, NDCG использует исходную шкалу 0–3.

В основной оценке все запросы ищут по 3 280 карточкам. У validation в среднем
доступны 99,80% бинарно релевантных товаров, но средний потолок NDCG@10 равен
0,908 из-за размеченных товаров за пределами каталога.

### Результаты baseline

Источник: `reports/baseline_metrics.csv` и `metrics_summary` в тетради 03.

| Метод | MRR | NDCG@10 | Recall@10 | HitRate@10 |
| --- | ---: | ---: | ---: | ---: |
| TF-IDF | 0,376 | 0,437 | 0,529 | 0,629 |
| Семантический MiniLM | 0,243 | 0,246 | 0,310 | 0,414 |

На этом baseline лексический поиск выигрывает по всем зафиксированным метрикам.
Разбор `error_queries` показывает три запроса с точными формулировками, где
TF-IDF ставит relevance-3 товар на первое место, а семантическая модель не
находит релевантный товар в top-10: искусственные шубы с капюшоном, сабо с
брендом и классические кожаные топсайдеры.

### Гипотезы третьей недели

1. Сокращение или изменение шаблона `product_text` повысит качество эмбеддинга
   за счёт снижения влияния длинных описаний.
2. Гибрид TF-IDF и семантических score сохранит точные совпадения и поможет на
   запросах с синонимами.

### Ограничения

- Модель усекла 35,52% товарных текстов; baseline не компенсирует это.
- Оценка неполна: неразмеченная выдача считается нерелевантной.
- Официальный test не открывался и будет использован ровно один раз после
  выбора конфигурации на development/validation.

## Неделя 3 — эксперименты, MLflow и заморозка выбора

### Зафиксированный протокол

`protocol_manifest.json` сохраняет fingerprints каталога, split, golden-set и
baseline-манифеста. Эксперименты используют неизменные 3 280 карточек, 560
development-запросов, 140 validation-запросов, `SEED=42`, `relevance >= 2` и
`K=(1,3,5,10)`.

### Эксперименты validation

Источник: `reports/validation_experiment_comparison.csv`.

| Конфигурация | NDCG@10 | MRR | Решение |
| --- | ---: | ---: | --- |
| TF-IDF baseline | 0,437 | 0,376 | Победитель |
| RRF-гибрид, alpha=0,25 | 0,424 | 0,378 | Отклонён по основной метрике |
| MiniLM, полный текст | 0,246 | 0,243 | Baseline семантики |
| MiniLM, короткий текст | 0,178 | 0,182 | Отклонён |
| MiniLM с общей проекцией | 0,096 | 0,120 | Отклонён |

Короткий текст устранил усечение, но потерял смысловые детали описаний.
Гибрид улучшил MRR и Precision@5, однако ухудшил NDCG@10. Проекция обучалась
на development-триплетах с релевантностью ≥2 и явными размеченными
отрицательными товарами, но не перенеслась на validation.

### MLflow

Эксперимент `calmfruits_semantic_search` содержит завершённые validation-runs
`lexical`, `semantic_full_text`, `semantic_short_text`, `hybrid_rrf` и
`semantic_projected`. В каждом есть обязательные параметры и метрики.
Учебный `check_mlflow.py` получен из шаблона ProjectMonth и завершился без
замечаний.

### Замороженная финальная конфигурация

По правилу max NDCG@10, затем MRR, выбран TF-IDF. Файл
`reports/selected_configuration.json` фиксирует победителя, MLflow run ID и
fingerprints до открытия test. Test-разметка в этот момент не читалась.

### Единственная финальная оценка

Источник: `reports/final_test_metrics.csv`, checkpoint
`artifacts/final/final_test_state.json` и final MLflow run
`eea52cfcb9ef4bdd826a3a09287bfc2c`.

Замороженный TF-IDF обработал 300 test-запросов по каталогу из 3 280 карточек:
NDCG@10 — 0,414, MRR — 0,342, Recall@10 — 0,530, HitRate@10 — 0,637,
Precision@10 — 0,123. Checkpoint имеет статус `completed`; повторное
исполнение финальной тетради загрузило сохранённый результат и не запускало
поиск по test повторно.

### Качественный анализ ошибок

В трёх запросах с минимальным NDCG@10 — «свободные рубашки», «футболки lovetex
store» и «легкие костюмы» — все бинарно релевантные размеченные товары доступны
в каталоге (`reachable_relevant_share=1`), но не вошли в top-10. Выдача
содержит предметно близкие рубашки, футболки и костюмы, однако не удовлетворяет
свободной формулировке, брендовому запросу или атрибуту лёгкости.

### Рекомендация бизнесу

Для текущего MVP не заменять ключевой поиск исходным векторным подходом:
TF-IDF выиграл NDCG@10 на validation и был заморожен для test. Он хорошо
обрабатывает точные товарные, брендовые и атрибутивные совпадения. Векторный
поиск стоит продолжать как кандидата для будущего гибрида, но только после
проверки на реальных пользовательских логах.

### Дальнейшие шаги

1. Собрать реальные запросы, показы, клики и покупки, чтобы заменить
   синтетическую и неполную разметку поведенческим сигналом.
2. Добавить нормализованные брендовые и атрибутивные фильтры поверх выдачи.
3. Проверить более сильный гибрид и обучение эмбеддера на отдельной
   validation-выборке, не меняя замороженный test-протокол.
4. При масштабировании каталога заменить полный перебор на ANN-индекс и
   проверить его recall относительно точного поиска.
