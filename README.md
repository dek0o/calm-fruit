# CalmFruits: MVP семантического поиска товаров

## Задача

CalmFruits проверяет, улучшает ли векторный поиск товаров по текстовому запросу существующий поиск по ключевым словам. MVP решает задачу query-to-item: по короткому запросу пользователя система возвращает top-K карточек товара (`imt_id`) из каталога одежды и обуви.

Сравниваются лексический поиск (TF-IDF) и семантический поиск на эмбеддингах `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` с одинаковым интерфейсом `search_xxx(query, top_k)`, а также три эксперимента: короткий текст товара, гибрид TF-IDF и MiniLM через Reciprocal Rank Fusion и обучаемая проекция поверх замороженного энкодера.

## Итоги

Каталог оценки — 4 256 карточек (подготовленный каталог «Одежда» и «Обувь», ограниченный пулом асессоров); golden-сет — 140 validation-запросов из train; порог релевантности `relevance >= 2`, K = 1, 3, 5, 10, NDCG по шкале 0–3.

| Конфигурация | Выборка | NDCG@10 | MRR | Recall@10 | HitRate@10 |
| --- | --- | ---: | ---: | ---: | ---: |
| RRF-гибрид TF-IDF + MiniLM (выбран) | validation | 0,460 | 0,157 | 0,339 | 0,450 |
| TF-IDF (baseline) | validation | 0,459 | 0,169 | 0,320 | 0,450 |
| MiniLM, полный текст | validation | 0,231 | 0,117 | 0,171 | 0,257 |
| MiniLM, короткий текст | validation | 0,188 | 0,144 | 0,214 | 0,286 |
| MiniLM + обучаемая проекция | validation | 0,096 | 0,136 | 0,146 | 0,229 |
| RRF-гибрид TF-IDF + MiniLM | test (300 запросов) | 0,424 | 0,152 | 0,296 | 0,407 |

Чистый семантический поиск вдвое уступает лексическому; гибрид с малым весом семантики равен TF-IDF по NDCG@10 и немного полнее. Рекомендация бизнесу, разбор ошибок, ограничения и дальнейшие шаги — в конце тетради и в `semantic_search_project_workbook.md`.

## Структура репозитория

```text
semantic_search_project.ipynb        тетрадь: EDA, пайплайн, оценка, эксперименты, MLflow, выводы
semantic_search_project_workbook.md  рабочий документ проекта
check_mlflow.py                      проверка эксперимента MLflow (из шаблона проекта)
requirements.txt                     зафиксированные зависимости
.env.example                         образец переменных окружения
.gitignore
```

При выполнении тетрадь создаёт папки `data/` (скачанные исходные файлы) и `artifacts/` (эмбеддинги `.npy`, метрики по запросам, графики, результат финального теста). Обе папки не хранятся в репозитории и полностью воспроизводятся тетрадью.

## Окружение

- Python 3.12 (тетрадь выполнена на 3.12.6), вычисления на CPU.
- Зависимости с зафиксированными версиями — в `requirements.txt`.
- Единый `SEED = 42`.

## Запуск

1. Установите зависимости:

   ```bash
   python3.12 -m venv .venv
   source .venv/bin/activate
   python -m pip install -r requirements.txt
   ```

2. Получите параметры доступа кнопкой «Проверить» в уроках Практикума: ключи S3 — в уроке «Неделя 1. Постановка задачи проектного месяца», адрес, логин и пароль MLflow — в уроке «Неделя 3. Улучшение системы, логирование в MLflow, финальные выводы» (там же MLflow запускается).
3. Скопируйте `.env.example` в `.env` и заполните значения. Файл `.env` не попадает в Git.
4. Выполните тетрадь сверху вниз:

   ```bash
   jupyter nbconvert --to notebook --execute --inplace semantic_search_project.ipynb \
     --ExecutePreprocessor.timeout=3600
   ```

   или откройте её в Jupyter и выберите «Run All». Полный прогон на CPU занимает около 6 минут; при первом запуске скачиваются данные из S3 и модель с Hugging Face.

5. Проверьте эксперимент MLflow (эта проверка выполняется и последней ячейкой раздела MLflow в тетради):

   ```bash
   python check_mlflow.py calmfruits_semantic_search --env-file .env
   ```

## Данные

| Файл | Назначение |
| --- | --- |
| `wb_products_raw_sample.parquet` | сырой каталог, из него готовятся тексты товаров |
| `wb_products_dedup.parquet` | только список `imt_id` пула асессоров для каталога оценки |
| `queries_synthetic_train.parquet` | разметка для baseline, подбора параметров и валидации |
| `queries_synthetic_test.parquet` | один финальный прогон выбранной конфигурации |

Тестовая разметка используется один раз, после выбора конфигурации по validation. Результат сохраняется в `artifacts/final_test/`, и при повторном выполнении тетради для той же конфигурации загружается, а не пересчитывается.
